# Job Hunter MCP

Персональный MCP-сервис для поиска IT-вакансий и управления резюме/черновиками откликов. MCP-сервер написан на Go; язык Go не является поисковым навыком кандидата и не добавляется в поисковый профиль автоматически.

## География поиска

- `izhevsk`: поиск через SuperJob с идентификатором города `SUPERJOB_IZHEVSK_TOWN_ID`; доступность вакансий зависит от фильтров API.
- `russia_remote`: поиск удалённых вакансий через SuperJob.

## Запуск

```bash
cp .env.example .env
# Замените POSTGRES_PASSWORD и REDIS_PASSWORD и установите длинный случайный MCP_AUTH_TOKEN
# При необходимости заполните SUPERJOB_APP_ID / SUPERJOB_ACCESS_TOKEN
docker network create openclaw-mcp # только если общей сети ещё нет
docker compose up -d --build
docker compose logs -f job-hunter-mcp
curl http://127.0.0.1:8092/healthz
```

Compose подключает `job-hunter-mcp` и к своей внутренней сети `default` (вместе с PostgreSQL и Redis), и к существующей внешней Docker-сети `openclaw-mcp`. PostgreSQL и Redis во внешнюю сеть не подключаются. Docker Compose публикует порт только на loopback хоста; клиент в другом контейнере той же сети должен использовать service DNS `job-hunter-mcp`.

MCP использует Streamable HTTP в stateless-режиме: `POST /mcp` на порту `8092`. Из OpenClaw-контейнера URL — `http://job-hunter-mcp:8092/mcp`; с хоста — `http://127.0.0.1:8092/mcp`. Передавайте `Authorization: Bearer <MCP_AUTH_TOKEN>`. `MCP_AUTH_TOKEN` обязателен и должен содержать не менее 32 символов. `POSTGRES_PASSWORD` и `REDIS_PASSWORD` имеют небезопасные значения по умолчанию и должны быть заменены; `DATABASE_URL` в Compose автоматически направляется на service DNS `postgres`. Redis по умолчанию доступен по `redis:6379`, использует базу `0`, сохраняет данные в volume и требует пароль из `REDIS_PASSWORD`. `CACHE_TTL` задаёт срок хранения результатов (по умолчанию `5m`). `SUPERJOB_APP_ID`, `SUPERJOB_ACCESS_TOKEN` и `SUPERJOB_IZHEVSK_TOWN_ID` — необязательные настройки SuperJob API.

`/healthz` возвращает `200` без авторизации и доступен для проверки готовности по HTTP. Проверки готовности настроены для PostgreSQL и Redis; приложение ожидает их готовности при запуске.

Поиск и получение вакансий выполняются через SuperJob API. Для запросов нужны `SUPERJOB_APP_ID` и, если выдан, `SUPERJOB_ACCESS_TOKEN`; Ижевску также нужен `SUPERJOB_IZHEVSK_TOWN_ID`. HTTP 403 означает, что сервер API отклонил запрос; проверьте параметры доступа приложения и разрешения API.

## MCP tools

- `list_resumes` — список сохранённых резюме.
- `save_resume` — сохранить извлечённый текст и профиль резюме. Агент должен прочитать вложенный PDF/DOCX, извлечь текст, структурировать профиль и передать только подтверждённые факты.
- `search_vacancies` — поиск по выбранному запросу и географии.
- `get_recent_vacancies` — последние вакансии в БД.
- `save_application_draft` — сохранить черновик сопроводительного письма, не отправляя его.

Redis кэширует результаты `list_resumes`, `get_vacancy` и `get_recent_vacancies` с TTL `CACHE_TTL`. Запросы кэша учитывают имя инструмента и все его аргументы; успешные `save_resume`, `save_application_draft` и `search_vacancies` инвалидируют кэш. Ошибки Redis возвращаются вызывающему MCP-клиенту явно.

## Передача резюме агенту

Пользователь отправляет PDF/DOCX агенту OpenClaw. Сам агент (или его file/document skill) извлекает текст, формирует JSON-профиль и вызывает `save_resume`. В текущей версии MCP не принимает бинарные вложения напрямую: это намеренно оставляет разбор документов на стороне OpenClaw и позволяет не привязывать сервер к конкретному формату/парсеру. Оригиналы файлов в этой версии не сохраняются автоматически.

Пример профиля:

```json
{
  "roles": ["PHP Backend Developer"],
  "skills": ["PHP", "Laravel", "PostgreSQL", "Docker"],
  "experience_years": 3,
  "projects": [],
  "education": [],
  "achievements": [],
  "preferred_roles": [],
  "facts_source": "resume"
}
```

Пустые или неизвестные поля оставлять пустыми. Не выводить навыки из косвенных упоминаний. Не добавлять Go, пока пользователь явно не подтвердит этот навык.

## Важные ограничения первой версии

1. SuperJob — источник вакансий; условия использования API обязательны к соблюдению.
2. Хабр Карьера, Geekjob и Работа России пока не подключены: не использовать HTML-скрейпинг в обход ограничений; подключать только после проверки разрешённого API/канала.
3. Полный текст вакансии пока ограничен данными выдачи SuperJob; следующий этап — отдельные методы детализации вакансии и нормализация требований.
4. Оценку ATS/HR делает языковая модель OpenClaw по доступным текстам. Она не может достоверно знать закрытые алгоритмы работодателя и не должна обещать 100% прохождение.
5. Отклики автоматически не отправляются. MCP сохраняет черновики; подтверждение пользователя обязательно.
6. Для реального использования добавить TLS/reverse proxy при доступе вне localhost, резервное копирование БД и безопасное хранение ключей.

## Пример конфигурации OpenClaw

Если OpenClaw работает в контейнере, подключённом к сети `openclaw-mcp`, настройте сервер `job-hunter` на URL `http://job-hunter-mcp:8092/mcp` с заголовком `Authorization: Bearer <MCP_AUTH_TOKEN>`. Если OpenClaw работает на хосте, используйте `http://127.0.0.1:8092/mcp`. Конкретная команда регистрации зависит от установленной версии OpenClaw.
